## What the product is

**AccumenAI** (previously codenamed **Monetix** — old name still appears in docs, table prefixes, and `demo/` backups) is a **multi-tenant, multi-industry business-management SaaS monolith**. One Laravel application serves:

- **Industries**: Education (institutes), Healthcare/HMS (hospitals, labs, pharmacy), Training centers, and generic commerce/retail — selected per tenant via `institutes.industry` + `industries`/`sub_industries` taxonomy.
- **Business domains implemented**: Sales, Purchase, Inventory, Accounting/Finance (double-entry), Tax/TDS/VAT, Fixed Assets, HR & Payroll, CRM, Education/Academic, Medical (large HMS), Training Center, Documents, Notifications, Reports, AI assistant, SaaS packaging/billing.
- **Domains registered but NOT implemented**: POS, Manufacturing, Real Estate, Restaurant (see below).

Primary market signal: Bangladesh-first (`locale.country.default_name = 'Bangladesh'`, geo tables, bKash gateway, DGDA drug registry, TDS/VAT) but with country config for ~43+ countries.

## Current architecture

Laravel 12 monolith, **MVC + Service Layer**. Not a repository pattern, not DDD.

```
Route → Middleware(aliases) → Controller (thin-ish) → Service (business logic) → Eloquent Model → MySQL
                                                                    ↘ JournalPostingService / InventoryStockService (financial + stock engines)
```

- **358 controllers**, **392 service classes** (the real business logic lives here), **421 model files**, **974 Blade views**, **21 Livewire components**, **74 artisan commands**.
- **2156 registered routes** (1075 GET / 763 POST / 142 PUT / 137 DELETE / 37 PATCH-family).
- Static request context objects (`TenantContext`, `BranchContext`) + **global scopes** on Eloquent models provide tenancy.

## Multi-tenant model

**Single database, row-level isolation** (no subdomains, no per-tenant DB).

```
User (global person)  --Membership (table `institution_user`)-->  Institute (tenant)  -->  Branch
                                                                        ↓
                                                          business tables carry `institute_id`
```

- **Tenant column**: `institute_id` (NOT `organization_id`, NOT `tenant_id`).
- **Tenant context**: `App\Support\TenantContext` (static) + `App\Support\BranchContext`.
- **Populated by**: `App\Http\Middleware\SetTenantContext` (alias `tenant`), which is **prepended before `SubstituteBindings`** in `bootstrap/app.php:101` — this ordering is load-bearing, do not change it.
- **Enforcement**: `App\Models\Concerns\TenantScoped` global scope → `WHERE institute_id = TenantContext::id()`. Used by **223 of 421** model files.
- **Branch axis**: `App\Models\Concerns\BranchScoped` (75 model files reference it). No-op when branch id is null → owner/admin sees all branches.
- **Owner/staff workspace switching**: `App\Support\Workspace` (session key `active_institution_id`), re-verified against an active `Membership` on every request; forged workspace id → 403.
- **CRITICAL**: if `TenantContext` is not set (null), `TenantScoped` is a **no-op** and all rows are visible. This is intentional for CLI/platform-admin, but any HTTP path that forgets the `tenant` middleware silently loses isolation.

**Medical/HMS does NOT use the global scope.** `app/Models/Medical/*` (76 models) have **zero** `addGlobalScope` usage; they rely on **manual** `where('institute_id', MedicalScope::instituteId())` in controllers. Isolation is per-query discipline, not framework-enforced.

## Critical business rules

1. **Tenant owns everything.** `TenantScoped::creating()` force-sets `institute_id` from context and `updating()` reverts any attempt to dirty `institute_id` or `created_by` (`app/Models/Concerns/TenantScoped.php:46-68`).
2. **Owner/staff cannot cross.** Enforced in `Membership` (create/update) and `User::assertAccountTypeConsistentWithMemberships()`.
3. **Owner bypasses permission matrix.** `Membership::hasPermission()` → `if ($this->isOwner()) return true;`.
4. **Teachers are denied finance.** `DenyTeacherFromFinance` middleware denies `teacher` role on `finance*`/`accounting*` URIs — a **deny-list (fails open for everyone else)**.
5. **Finance write gate** (`FinanceWriteGate`) denies only `receptionist` + `branch-manager` on a hard-coded URI list — **also fails open**; its own docblock states the permission matrix was empty when written.
6. **Journals must balance.** `JournalPostingService` enforces `sum(debit)==sum(credit)`, ≥2 lines, no line with both sides, period must be open; posted journals are never hard-deleted (reverse/void only) — `app/Services/Accounting/JournalPostingService.php`.
7. **Inventory movements are the source of truth**; `inventory_stock_levels` is a cached balance kept in sync under `SELECT ... FOR UPDATE` with **weighted-average costing** — `app/Services/Inventory/InventoryStockService.php` class docblock.
8. **`InventoryStockService` is the single write path** for quantity changes (receive/saleIssue/transfer/postAdjustment/postCount/returnStock).
9. **Feature/module entitlement** is resolved per-tenant: `module_registry` + `feature_registry` + `package_features` + per-institute overrides → `ModuleAccessService::isEnabled()/isFeatureEnabled()`, enforced by `module_access:` / `feature:` middleware. **`PlatformAdmin` bypasses all of them.**
10. **Advanced accounting is a tenant-level toggle** (`institutes.advanced_accounting_enabled`); `advanced.accounting` middleware 403s when off.

## Important database rules

- **PK**: `bigint unsigned AUTO_INCREMENT` everywhere; `uuid char(36)` also present on most tenant tables (secondary identifier). **No UUID PKs.**
- **Human UID**: `users.uid` (10 chars: 6 alnum + 4 numeric) generated by helper/fallback.
- **Tenant column is `institute_id`** on tenant tables; membership pivot uses **`institution_id`** (inconsistent naming — `institution_user.institution_id` vs everywhere else `institute_id`).
- **`Membership` model → table `institution_user`** (singular), while legacy `InstituteUser` → table `institute_users` (plural). Two coexisting account tables.
- Base schema comes from **`database/schema/mysql-schema.sql` dump**, NOT from migrations. `database/migrations` (240 files, all dated 2026-09-13 → 2026-09-27) only cover incremental deltas + registry seeding. **`php artisan migrate` on an empty DB will NOT produce a working schema.**
- Tests assume a **pre-provisioned** test DB (`monetix_test`) loaded from `database/schema/full_data.sql`, using `DatabaseTransactions` (no migrate) — see comment in `phpunit.xml`.
- Soft deletes are common but NOT universal (`users`, `institutes`, `branches`, `institution_user`, `students` have them; several ledger tables do not).

## Security model (architecture-level)

- Middleware stack per web request: `AssignRequestId → NormalizePersonNames → SetLocale → SecurityHeaders → PlatformMaintenance`, then `SetTenantContext` (before route-model binding), then route-level `auth` / `permission` / `module_access` / `feature` / `verified`.
- `SecurityHeaders` sets CSP, X-Frame-Options DENY, HSTS, nosniff, Referrer-Policy — applied to **all web responses**.
- CSRF: standard Laravel (`web` group). 419 handling customized (friendly logout redirect) in `bootstrap/app.php`.
- reCAPTCHA v3 on login/register/password forms (`.env` keys; empty = disabled).
- Rate limiting: `throttle:30,15` (user login), `throttle:10,15` (admin login), `throttle:10,1` (OTP/2FA/API login), `throttle:60,1` (API), plus custom friendly-429 rendering.
- Password hashing: bcrypt (`BCRYPT_ROUNDS=12`), with idempotent setter + daily `auth:audit-hashes` schedule.
- See `docs/ARCHITECTURE_AUDIT_REPORT.md` for classified findings.

4. **`SalesInventoryIntegration` is orphaned** — no callers anywhere; its docblock says "Later Sales steps will call these helpers."

9. **Schema not migration-reproducible** — see "Important database rules".
10. **`TenantContext` is static/process-global** — queued jobs and long-running workers inherit whatever was last set; no request-scope restoration.
11. **CRITICAL: five git-tracked debug scripts in the webroot** — `public/_probe_admin.php`, `public/_dash_theme_test.php`, `public/_pagination_verify.php` bootstrap the app and call `Auth::loginUsingId(1)` as `PlatformAdmin` (then render views/dump data); `public/step127_safety.php` and `public/step127_verify.php` dump row counts/schema. `public/.htaccess` serves existing files directly (`!-f`), so they run with no Laravel middleware/auth. ## Development rules

Follow `docs/AI_DEVELOPMENT_RULES.md` (derived from actual code). Headlines:

- New tenant models: add `use Concerns\TenantScoped;` (+ `BranchScoped` if the table has `branch_id`).
- Never query tenant data without tenant context; never hardcode `institute_id`.
- Routes: tenant CRUD → `routes/institute_modules.php` inside the `$tenant` group; HMS → `routes/medical.php`; platform admin → `admin/` prefix in `routes/web.php`.
- List pages: `->paginate(20)->withQueryString()` + Standard List Page Blade pattern.
- Migrations must be idempotent (`Schema::hasTable`/`hasColumn` guards) — the project's migrations re-run over an existing dump.
- Business logic goes in a **Service**, not the controller. Controllers validate (FormRequest or inline) and delegate.
- Money math: use decimal casts / `round(..., 2..4)`; never floats for persisted totals.
- Tests: `DatabaseTransactions` (never `RefreshDatabase` — schema comes from a dump).

## MUST NOT be changed casually

1. The `SubstituteBindings` / `SetTenantContext` priority reorder in `bootstrap/app.php:101`.
2. `TenantScoped` / `BranchScoped` global scope logic (a bug here = cross-tenant data leak).
3. `Membership::assertRoleAllowedForAccountType()` and the owner/staff invariant.
4. `password_hash` column naming + `getAuthPassword*()` overrides.
5. `JournalPostingService` balance/immutability invariants.
6. `InventoryStockService` as the single stock write path (never write `inventory_movements` directly).
7. `institution_user` table name / `Membership::$table` (legacy naming, referenced in raw `DB::table()` calls too — e.g. `SetTenantContext.php:61`).
8. The `TenantContext` null = unrestricted semantics (CLI and platform admin depend on it).
9. `database/schema/mysql-schema.sql` as the schema source of truth.

## Investigate before modifying anything

- Whether your change touches **medical** models → check whether that model has global scope (it probably doesn't) and add explicit `institute_id` filters.
- Whether your route group carries `auth` + `tenant` + `verified` + `permission`/`module_access` (compare with an existing sibling group in the same file).
- Whether `role_permissions` actually grants the slug you're gating on (grants are seeded per-role by `RolePermissionSeeder` + `RoleTemplateSeeder`; the matrix is NOT universal).
- Whether the feature is tenant-enabled (`ModuleAccessService`) before wiring UI.
- Whether `advanced_accounting()` is on for the tenant.
- Whether a test pre-supposes seeded data in `monetix_test` (tests do not migrate).
